# 道路商家分布分析产品业务架构

P0 业务方案审核稿    V0.3    2026年10月16日

P0 以道路与商家 POI 的空间关联为核心，形成“省—市—区县看道路商家分布，进入道路看商家位置”的业务闭环。本方案仅定义业务功能、分析对象和统计规则，供审核与决策。

## 1 业务目标与分析层次

区域分析回答各市、区县的道路商家规模、密度与行业差异；道路分析回答哪些道路商家更多、更加集中以及主要经营什么；单路分析回答具体商家在哪里、沿路分布是否均匀。

道路范围以客户提供并按其业务条件过滤后的全省道路数据为准，空间关联候选与道路长度统计统一使用该范围。产品直接使用该数据集，不另行定义道路纳入或排除清单。

行政层级固定为省、市、区县，支持下钻和向上汇总。道路按区县边界拆分，形成区县道路单元，作为道路统计与分析的基本单元；市、省由其向上汇总。区县以下不再增加行政层级。

## 2 业务功能架构

| 功能域 | 业务问题 | P0 功能 |
| --- | --- | --- |
| 行政层级分析 | 区域之间分布有何差异 | 省、市、区县逐层统计、比较及汇总，定位到区县内道路。 |
| 道路分布分析 | 各条道路分布有何差异 | 以区县道路单元比较商家数量、密度和行业结构，支持排序。 |
| 单条道路分析 | 这条道路的商家在哪里 | 查看一个区县道路单元内的商家位置、明细及沿路分布。 |
| 分类维度 | 希望按什么条件分析 | 按道路适用等级、商家一二级行业筛选统计；自定义标签仅预留。 |
| 关联与统计规则 | 结果如何形成并保持一致 | 统一门店计数、道路与 POI 空间关联及最小距离兜底、区县拆分和逐层汇总。 |
| 特殊场景规则 | 路口和环路如何处理 | 补充交叉点、环路、跨区道路及主辅路等场景的业务判定要求。 |

行政层级分析、道路分布分析和单条道路分析构成业务主线；分类维度贯穿主线，关联与统计规则及特殊场景规则共同保障结果可信。

## 3 核心业务功能

### 行政层级分析

省级比较各市，市级比较各区县；在对应区域范围内查看道路关联商家数量、道路商家密度及行业构成。区县级查看本区县各道路单元的统计结果，市、省按这些单元汇总。下钻和上聚合持续保留已选分类条件，结果使用相同统计口径。

### 道路分布与单路分析

区域内道路支持按商家数量和密度比较、排序，并按照道路等级进行同类比较。商家总量表达分布规模，每公里商家数表达分布密度，两者分别展示，避免把长道路的规模误认为高密度。

进入一个区县道路单元后，明确道路名称、等级及所属区县；查看商家总数、密度、行业结构、具体位置和商家明细。单元内部能够区分集中、稀疏和无商家路段；商家位置采用实际经营位置。

跨区道路在不同区县分别形成道路单元，分别统计与分析；保留原道路身份用于识别来源关系。P0 不设置跨区完整道路的独立查看范围，市、省直接汇总区县道路单元。

### 道路等级与商家行业

道路按照适用的国家、行业标准分类，保留分类体系和等级两个属性。城市道路等级与公路技术等级、公路行政分类分别表达，不混成单一等级序列；同一业务道路允许不同部分具有不同等级。等级缺失时标记待确认，不凭路名推断。

城市道路可按快速路、主干路、次干路、支路分类；公路技术等级另按高速公路、一级至四级公路分类。实际分析使用经核定的等级来源和映射，按适用体系筛选与比较。

商家行业采用已有的一、二级业态，支持从行业大类进一步细分；未知行业单独保留。自定义标签作为后续统计维度预留，本期不要求标签创建、维护或标签分析功能。

### P0 最小指标集

| 指标 | 业务含义 |
| --- | --- |
| 商家数量 | 区域商家总量及道路主归属商家数，分别标明口径。 |
| 道路商家密度 | 符合当前条件的主归属商家数除以对应道路长度，单位家／公里。 |
| 行业结构 | 商家按统一主行业分组的数量与占比，包含未知行业。 |
| 沿路分布 | 道路内部各部分的商家数量与密度，反映局部集中或稀疏。 |

## 4 业务对象与统计口径

| 对象 | 定义 |
| --- | --- |
| 原道路 | 拆分前的道路来源对象，保留身份与名称；同名不直接视为同路，多条记录也不直接视为多路。 |
| 区县道路单元 | 按区县边界拆分后的基本统计与分析对象，由原道路身份及所属区县共同区分，可包含多个片段。 |
| 分析路段 | 区县道路单元内部用于观察分布差异的道路部分，不属于行政层级。 |
| 商家 | 以实际经营门店或经营点计数；重复 POI 合并，不同门店分别统计。 |
| 商家道路关系 | 每店按空间关系唯一关联到一个区县道路单元；不能确定时按最小距离兜底，保留关联方式。 |

### 商家归属

商家行政归属以 POI 实际经营位置为依据，候选道路限定在该区县内的客户道路数据范围。根据 POI 点与道路线或道路范围的空间关系建立候选并确定唯一主归属；不能确定时，直接采用最小距离兜底。同距时采用固定优先顺序，保证结果唯一且稳定。关联不依赖 address、地址道路名称或 POI 道路字段的完整性与规范性。

空间判定与最小距离兜底的结果均直接进入正式道路统计及商家明细，保留关联方式。兜底结果无需另行检查、抽样验证或人工确认，也不设置兜底占比、归属准确率等验收门槛。仅在坐标无效、行政归属无法确定或本区县无可用道路等数据异常下保留未关联；地址缺失或不规范不影响空间关联。

### 逐层汇总与对账

在相同数据时点、行政范围和商家条件下，未按道路等级筛选时：区域商家总量＝空间判定关联商家数＋最小距离兜底商家数＋数据异常未关联商家数。各区县道路单元的商家合计等于本区县已关联商家数，一店只计一次。边界商家先明确唯一所属区县，再在该区县内进行空间关联。

区县汇总本区县道路单元，市汇总下辖区县，省汇总下辖市。上层密度以总商家数除以对应总道路长度，不能直接平均下层密度；长度仅计算拆分后落入本区县的部分，包含零商家道路，不重复累计原道路。道路详情数量应与同单元的商家明细对应。

行业条件作用于商家范围；道路等级条件作用于已形成的空间关联结果和对应道路长度。跨等级道路依据商家空间关联到的道路部分参与筛选，并统计该部分长度。区域商家总量及未关联数量不因道路等级改变，应明确其适用范围。

无有效道路长度时，密度标为不适用。未来多标签统计按商家去重，多标签数量不能直接相加为商家总量。

### 道路空间数据的业务约束

现有道路数据提供 path 道路线与 boundaries 道路 Shape 表达，P0 不要求两者同时使用。业务上应保持道路范围和计量口径统一，不因存在两份空间表达而重复计算道路或商家。具体选择不在本方案展开。

## 5 专业分析能力与特殊场景

专业分析能力集中于 POI 点与道路线或道路范围的空间关联、沿路分布识别及特殊场景处理。空间规则不能确定唯一归属时，直接按最小距离兜底；本方案不展开具体算法参数或计算实现。

| 场景 | 必须满足的业务要求 |
| --- | --- |
| 交叉点 | 在所属区县内按空间关系判定候选道路，不能确定则最小距离兜底；一店唯一归属，不按道路等级高低强制归属。 |
| 环路 | 区分实际闭合与仅名称含环。区县内闭合环路不因人为起点产生断点；跨区拆分后按实际片段分析，不跨区连接。 |
| 跨区道路 | 按区县边界拆分，各单元独立统计，上层由下层汇总；商家只在唯一所属区县内关联与计数。 |
| 主辅路与立交 | 根据 POI 与各道路的空间关系判定，不能确定则最小距离兜底，直接计入对应道路单元。 |
| 同名与多段道路 | 保留正确道路身份，避免误合并或误拆分。 |

## 6 P0 完成的业务标准

1. 在客户提供并按其条件过滤后的全省道路范围内开展分析，支持省—市—区县下钻与汇总。
2. 能按道路等级、商家行业查看数量、密度和结构差异。
3. 能从区县道路单元查看空间关联的商家位置、明细及沿路分布。
4. 空间判定不能确定唯一归属时直接执行最小距离兜底，一店只计一次，不以地址字段为前提，不设兜底检查或验证要求。
5. 道路及长度按区县拆分；环路按实际片段分析，各层数量、长度及明细能够对账。
