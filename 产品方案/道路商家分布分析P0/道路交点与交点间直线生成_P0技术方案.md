# 道路交点与交点间直线生成 P0 技术方案

## 1. 目标与范围

针对单个地市约十万条道路片段，使用 PostgreSQL/PostGIS 计算原始道路片段的交点，排除纯切割产生的连接点，再按同一道路的空间顺序，将相邻交点两两连接为直线。

核心路线为：**原始片段求交 → 交点归并与局部拓扑判定 → 道路内片段定向 → 交点事件排序 → 两点生成直线**。

不需要先恢复完整道路，也不先连接缺失片段后求交。道路缺失只影响可发现的交点，不阻止连接顺序已经明确的已有交点。

### 1.1 已确定的业务规则

| 项目 | 实施口径 |
| --- | --- |
| 来源片段标识 | 同一城市、同一批次内，`(osm_id, type, road_name)` 唯一；另设内部 `fragment_id` |
| 道路识别 | 地市、标准化道路名称、道路类型；必要时按区县细分 |
| 片段顺序 | 同一道路内，`osm_id` 的数值顺序就是空间先后顺序，视为输入数据契约 |
| 坐标 | 输入、工作几何、输出统一 WGS84，EPSG:4326；X 为经度，Y 为纬度 |
| 排除范围 | 排除高架、高速；其余道路按普通道路处理，不判断真实立体通行关系 |
| 交点 | 保留空间交叉和接触，排除同一道路被切割形成的纯连续连接点 |
| 缺失片段 | 不补原始线、不推测缺失位置的交点；允许跨缺失部分连接已有交点 |
| 输出几何 | 每条结果只有两个端点，直接生成 `LineString`，不保留原道路曲折形状 |
| 二次求交 | 输出直线不再参与交点计算 |
| 无法确定的数据 | 记录原因与来源；不把无法确定的拓扑或排序默认为正确 |

### 1.2 P0 不实施的功能

不进行道路名称模糊匹配、米级吸附、断路修复、缺失道路形状推断、真实通行拓扑推断、路径规划或分布式计算。结果线段的长度是交点间连接线长度，不是实际道路里程。

## 2. 实现架构与参数

采用单数据库离线批处理。PostGIS 完成空间操作，SQL 窗口函数完成排序和成线；片段方向的动态规划可用 PL/pgSQL 实现。无需引入图数据库或 pgRouting。

本方案使用 `ST_DumpSegments`，因此功能基线为 PostGIS 3.2 或以上；部署使用组织支持的 PostgreSQL/PostGIS 组合，并记录 `version()`、`postgis_full_version()`。这里的 3.2 是函数可用性下限，不是要求部署旧版本。[1]

| 参数 | P0 初始值或规则 | 含义 |
| --- | --- | --- |
| `city_code` | 单个城市代码 | 一次运行的处理边界 |
| `use_county` | 默认 false，按输入分组需要启用 | 启用后按区县分组，不跨区县道路组连线 |
| `numeric_eps_deg` | `1e-9` 度 | 仅用于计算误差归并、点在线上复核及端点一致性判断 |
| `orientation_tie_m` | `0.01` 米 | 两个定向方案代价近似相等的判定阈值 |
| `max_gap_m` | 不设拒绝阈值 | 用户允许片段缺失；记录距离，不因距离较长自动截断 |
| `pair_batch_size` | 初始 5000 个来源片段 | 控制求交中间结果规模，实测后调整 |
| `excluded_types` | 来源字典中的高速类别精确集合 | 不猜测实际 type 编码 |
| `excluded_fragment_ids` | 可选来源排除清单 | 补充高架等不能仅由 type 识别的记录 |

`numeric_eps_deg` 是角度容差，不是米。它不是道路定位精度，也不是容许道路相隔一段距离仍构成路口的业务阈值。正式交点只由原始几何求交产生；容差不用于把未相交道路变成相交道路。

距离、长度按米计算时使用 WGS84 `geography`，例如 `ST_Distance(p1::geography,p2::geography)`、`ST_Length(line::geography)`。4326 的 `geometry` 长度单位是度，不能直接当米。[2]

## 3. 输入契约与道路身份

### 3.1 输入字段

| 字段 | 要求 |
| --- | --- |
| `osm_id` | 可按数值排序；建议 bigint，超出范围时使用精确 numeric；不得按文本排序 |
| `type` | 原始道路等级或类型，保留原值并映射到 `type_norm` |
| `road_name` | 保留原值，另产生 `road_name_norm` |
| `geometry_wkt` | WGS84 LineString；原始文本保留用于追溯 |
| `city_code` | 若整份文件属于同一城市，由导入任务统一补入 |
| `county_code` | 仅在启用区县分组时必需 |
| 高架排除依据 | 可来自类型、已有高架标记或排除清单，不要求一定新增原始字段 |

**仅有道路名称、等级和二维 WKT，不能可靠判断是否高架。** 若来源 type 没有高架类别，导入时必须提供对应排除清单或来源标记；否则该批次不能宣称已完成高架排除。无需为本任务推断隧道、跨线桥。

道路名称只做首尾空白、重复空白等确定性清洗。不自动合并“某某路”“某某路辅路”，不删去“东段”“西段”等可能有意义的字样。

### 3.2 两层道路标识

为避免区县边界被错误当成路口，分开保存以下标识：

| 标识 | 组成 | 用途 |
| --- | --- | --- |
| `road_family_id` | 地市＋标准化名称＋标准化类型 | 判定是否同一道路系列，排除行政分组造成的纯连接点 |
| `route_id` | `road_family_id`＋可选区县＋必要的人工 `chain_id` | 排序与生成线段的最小道路组 |

默认 `chain_id=0`。如果一个名称和类型组合实际包括多条独立平行道路，且其 osm_id 不能构成一条明确序列，必须用来源信息或小型覆盖表拆组；不依据最近距离擅自把多条道路串起来。

用户给出的 osm_id 空间顺序契约适用于最终 `route_id`。实现不重新按经纬度、距起点直线距离或最近邻排序。

区县模式一旦启用，同名跨县道路会分组输出；本任务不增加行政区边界切线。跨县片段若没有唯一县归属，应保留城市模式或由输入侧明确分组，不以片段中心点随意分县。

### 3.3 输入校验

逐条捕获 WKT 解析错误，避免单条坏数据终止整批导入。使用 `ST_GeomFromText(wkt,4326)` 解析已确认属于 WGS84 的数据。`ST_SetSRID` 只标注坐标系，不进行坐标转换。[3]

校验空几何、非有限坐标、经纬度范围、城市范围明显异常、几何类型、重复组合键以及零长度。

- 连续重复顶点可删除，保留原始 WKT。
- LineString 自相交不能直接当作无效数据删除，按第 6.2 节处理。
- 不对原始数据执行整体 `ST_MakeValid`、吸附或合并后覆盖。
- MultiLineString 不默认按内部数组顺序当作道路顺序；写入异常表，明确子线顺序后再处理。
- 缺少名称不能把所有空名称记录合成一条道路。有效几何仍可参与求交，但该记录必须有单独的临时道路身份，且不跨片段连线。
- 同一自然键若对应不同几何，记录冲突，不能通过随意保留一条解决。

输入错误与用户接受的自然缺失分别统计，不能混在一起隐去。

## 4. 数据结构

所有业务与中间表均带 `run_id`；下表字段省略通用创建时间。所有跨表连接都必须限定同一运行批次。

| 表 | 关键字段 | 职责 |
| --- | --- | --- |
| `job_run` | run_id、city_code、参数 JSON、输入摘要、规则版本、状态 | 一次可重现运行 |
| `road_route` | route_id、road_family_id、city_code、county_code、name、type、is_closed、edge_ready | 道路分组与成线资格 |
| `road_fragment` | fragment_id、原始组合键、route_id、frag_seq、geom、direction、orientation_quality | 合格片段及顺序 |
| `intersection_pair` | fragment_a、fragment_b、intersection_geom | 每对片段一次求交结果 |
| `node_candidate` | candidate_id、geom、来源类别 | 未去重的点状交集 |
| `node_source` | node_id、fragment_id、candidate_id | 节点与来源片段的多对多关系 |
| `road_node` | node_id、geom、degree、family_count、node_kind、is_kept | 节点和分类结果 |
| `road_node_event` | event_id、route_id、node_id、fragment_id、frag_seq、fraction、event_seq | 某道路按顺序经过某节点的一次事件 |
| `road_edge` | route_id、edge_seq、start_event_id、end_event_id、start_node_id、end_node_id、geom、length_m、gap_count、quality | 最终两点直线 |
| `processing_issue` | issue_code、相关道路/片段/节点、详情、是否阻止成线 | 异常追溯 |

**节点与事件必须分开。** 同一个空间节点在一条有回绕的道路上可能被经过两次；节点只存一份，经过事件可以有多份。不能对 `(route_id,node_id)` 做全局唯一约束。

建议约束与索引：

```sql
CREATE INDEX road_fragment_geom_gix
    ON road_fragment USING gist (geom);

CREATE UNIQUE INDEX road_fragment_seq_uq
    ON road_fragment (run_id, route_id, frag_seq);

CREATE UNIQUE INDEX intersection_pair_uq
    ON intersection_pair (run_id, fragment_a, fragment_b);

CREATE INDEX road_node_geom_gix
    ON road_node USING gist (geom);

CREATE INDEX road_node_event_order_ix
    ON road_node_event (run_id, route_id, event_seq);

CREATE UNIQUE INDEX road_edge_seq_uq
    ON road_edge (run_id, route_id, edge_seq);
```

`geom` 分别声明为 `geometry(LineString,4326)` 或 `geometry(Point,4326)`；交集表使用通用 `geometry(Geometry,4326)`。入库完成和大批量中间表生成后执行 `ANALYZE`。

## 5. 片段排序与方向统一

### 5.1 确定片段序号

按 `route_id` 分组，按 osm_id 数值升序生成连续 `frag_seq`：

```sql
SELECT run_id, fragment_id, route_id,
       row_number() OVER (
           PARTITION BY run_id, route_id ORDER BY osm_id
       ) AS frag_seq
FROM road_fragment;
```

osm_id 不要求连续。编号跳号不能证明片段缺失，也不用于计算缺失数量。空间顺序相同的 osm_id 冲突必须在输入阶段解决，不靠其他字段偷偷打破并列。

### 5.2 为什么仍需要定向

osm_id 确定片段之间的先后，但 WKT 坐标可能反向。例如道路顺序为片段 1、2、3，而第 2 条 WKT 从后向前记录。若直接使用片段内比例，就会倒置该片段上的交点顺序。

每个片段有两个状态：0 为原方向，1 为 `ST_Reverse(geom)`。只选择方向，不改变片段顺序。

### 5.3 两状态动态规划

设第 i 个片段在状态 s 下的起终点为 `S(i,s)`、`E(i,s)`。相邻片段的转移代价：

```text
cost(i-1,t → i,s) = 米制距离(E(i-1,t), S(i,s))
DP(i,s) = min_t [DP(i-1,t) + cost(i-1,t → i,s)]
```

约束与执行方式：

1. 对相邻片段的四种端点组合计算距离。
2. 若存在数值容差内的首尾连接，转移只允许这些连接，避免用远距离缺口代价破坏已知连续关系。
3. 若四种组合均不连接，允许全部转移，按米制距离推断方向，并记录 `INFERRED_GAP`；不补线、不生成新交点。
4. 每个状态保存最优代价与回溯指针，避免复制整条路径导致二次复杂度；再逆序计算从该状态到末端的最小剩余代价 `B(i,s)`，其中 B 不重复计算已经到达 i 的转移。
5. 从末端回溯得到各片段方向。设全局最小代价为 C，则 `DP(i,s)+B(i,s) ≤ C+orientation_tie_m` 的状态都可能属于近似最优方案。前后向计算及回溯均为 O(n) 时间、O(n) 存储。
6. 无可行状态时记录 `ORDER_CONFLICT`。某片段两个方向均属于近似最优方案，且方向影响交点先后或边界重复事件合并时，保守记录 `ORIENTATION_AMBIGUOUS`，该道路不发布线段。不能仅检查两条候选路径就断言不存在其他歧义方案。
7. 只有一个非闭合片段时保留原方向；整体反向不影响其无向相邻配对。无交点且不承担交点边界合并的片段，其方向歧义不阻止输出。

可先完成交点发现，再判断歧义状态是否影响交点配对。实现首版采用上述保守规则，不需要枚举指数数量的定向路径。

方向质量为 `CONNECTED` 或 `INFERRED_GAP`。**跨缺失片段的最短端点距离是一条明确的推断规则，不是地理真值保证。** 输出携带该标记，并支持用 `fragment_id → direction` 覆盖表纠正个别片段。

同时检查：若同组的已知端点连接大范围跳过中间 frag_seq，或相邻编号片段只能在内部相接而不能首尾相接，记录 `ROUTE_CHAIN_CONFLICT`。这是输入不满足单条有序链的证据，不应通过重新按距离排序掩盖。

## 6. 原始几何求交

### 6.1 不同来源片段之间求交

在全部保留的道路片段之间求交，不能仅在同一路名内求交，也不能预先排除同一路名的片段对。

使用内部 `fragment_id` 约束每个无序片段对只计算一次，不能使用 `osm_id` 比较代替，因为 osm_id 的唯一性由原始组合键共同保证。

以下为关键 SQL 片段，`:run_id`、`:batch_from`、`:batch_to` 为任务参数，前提为上述表已建立：

```sql
INSERT INTO intersection_pair
       (run_id, fragment_a, fragment_b, intersection_geom)
SELECT a.run_id, a.fragment_id, b.fragment_id,
       ST_Intersection(a.geom, b.geom)
FROM road_fragment a
JOIN road_fragment b
  ON b.run_id = a.run_id
 AND a.fragment_id < b.fragment_id
 AND a.geom && b.geom
 AND ST_Intersects(a.geom, b.geom)
WHERE a.run_id = :run_id
  AND a.fragment_id >= :batch_from
  AND a.fragment_id <  :batch_to;
```

右表必须覆盖本城市全部有效片段，不能仅限同一批次区间，否则漏掉跨批次相交。批次区间互不重叠，恢复执行时先清理本批未完成结果或采用明确的幂等写入策略。

`ST_Intersects` 包含端点接触，且可利用空间索引过滤候选；不能只用 `ST_Crosses`，否则会漏掉丁字路口等接触关系。[4]

对交集分别提取点与线。交集可能包含多个点、线或混合结果，不能只读取第一个几何：[5]

```sql
-- 点状交集：每个点一条记录。
SELECT p.run_id, p.fragment_a, p.fragment_b,
       d.path AS point_path, d.geom::geometry(Point,4326) AS geom
FROM intersection_pair p
CROSS JOIN LATERAL
    ST_Dump(ST_CollectionExtract(p.intersection_geom, 1)) AS d
WHERE p.run_id = :run_id
  AND NOT ST_IsEmpty(d.geom);

-- 线状重叠：单独入 processing_issue，并保留重叠几何。
SELECT p.run_id, p.fragment_a, p.fragment_b,
       ST_CollectionExtract(p.intersection_geom, 2) AS overlap_geom
FROM intersection_pair p
WHERE p.run_id = :run_id
  AND NOT ST_IsEmpty(ST_CollectionExtract(p.intersection_geom, 2));
```

P0 不把重合线的两个端点直接当作路口。涉及未解决重叠的道路仍保留已发现交点，但 `edge_ready=false`，防止忽略重叠中的路口后错误跨越连线。其他道路继续处理。

### 6.2 同一片段内部自相交

只做 `a.fragment_id < b.fragment_id` 会漏掉一条 LineString 内部的自交。对 `NOT ST_IsSimple(geom)` 的片段追加局部检测：[6]

1. 用 `ST_DumpSegments` 拆成相邻顶点构成的基本直线段，保留 `atom_seq`。
2. 在该片段内部对基本线段求交，每对只计算一次。
3. 相邻基本线段仅共享一个公共顶点时，不新增候选；闭合线首尾基本段也按相邻处理。
4. 非相邻基本线段的点状交集进入同一个候选点流程。
5. 相邻或非相邻基本段产生线状重叠，均记录 `SELF_OVERLAP`，不静默忽略。

基本线段仅用于局部算法，不改变来源片段的 osm_id 或业务身份。少量自交片段按片段处理；顶点特别多时为基本段建临时 GiST 索引，避免局部暴力全配对。

## 7. 节点去重与纯切割点排除

### 7.1 数值归并

先按点的 XY 坐标精确去重，再对计算产生的极小误差进行归并。可用：

```sql
SELECT candidate_id,
       ST_ClusterDBSCAN(
           geom, eps => :numeric_eps_deg, minpoints => 1
       ) OVER (
           PARTITION BY run_id ORDER BY candidate_id
       ) AS cluster_id
FROM node_candidate
WHERE run_id = :run_id;
```

DBSCAN 使用几何坐标单位，其窗口排序用于确定性处理。[7] 归并必须保留全部来源片段关系。

每组采用按 XY、来源片段键排序得到的第一条原始候选点作为代表点，不使用均值点。检查每个成员到代表点的距离不超过 `numeric_eps_deg`；若出现聚类链式扩张，标记 `NODE_CLUSTER_AMBIGUOUS`，该组不自动合并或发布关联线段。不得默认为一个大路口。

不得用五米、十米等业务尺度聚类替代交点去重。这会合并相邻路口或双向车道交点，超出本次范围。

### 7.2 判定依据：局部拓扑度数

节点的度数 `degree` 指该位置伸出的独立线分支数量，去除重复、重合分支后计算。普通连续道路连接点通常为 2，丁字口为 3，十字口为 4。

**不能把所有片段首尾点删除，也不能把所有同名道路交点删除。** 首尾点可能恰好是真路口；同一道路也可能出现分叉、自交。

对每个候选节点，只收集 `node_source` 中关联的原始片段，计算局部线网，不对全城市做一次巨大 `ST_Union`：

1. 以代表点为参照，对关联片段进行仅在数值误差范围内的局部对齐；原始 geom 保持不变。
2. 使用 `ST_UnaryUnion(ST_Collect(local_geom))` 对局部线网进行节点化并消除重复线；`ST_Node` 也可用于节点化，但其输出方向和顺序不能作为道路排序依据。[8]
3. `ST_DumpSegments` 拆出局部基本线段。
4. 节点位于一个基本段的端点时贡献 1，位于内部时贡献 2，不在其上则贡献 0；累计得到 degree。先验证点在线上，不能用最近点强行关联远处线段。
5. 长度不超过数值容差、节点同时近似落在同一极短基本段的两端、或局部对齐不能得到一致分支结构时，记录 `LOCAL_TOPOLOGY_AMBIGUOUS`。

局部对齐可以使用 `ST_Snap(local_geom,node_geom,numeric_eps_deg)`，但必须复核输出是否真的经过代表点以及是否产生零长度或新的自交。该函数采用启发式，可能跳过某些吸附，不能把调用成功当作拓扑正确。[9] 无法确认时保留异常，不扩大容差反复尝试。

### 7.3 明确分类规则

| 条件 | 分类 | 处理 |
| --- | --- | --- |
| degree ≥ 3，来源关系明确 | `JUNCTION` | 保留，包含同一道路的分叉与自交 |
| degree = 2，只有一个 road_family_id，无重叠或拓扑异常 | `CONTINUATION` | 视为纯连续连接点，排除；不要求它一定是原始片段端点 |
| degree = 2，存在不同 road_family_id | `ROAD_CONTACT` | 保留，表示不同道路组的接触 |
| 同一道路仅因区县分组不同而接触，degree = 2 | `CONTINUATION` | 排除，区县边界本身不产生路口 |
| degree ≤ 1，或无法一致计算 | `UNRESOLVED` | 记录异常，不自动生成相关道路线段 |
| 交集包含重合线 | `OVERLAP` | 按第 6.1 节隔离 |

这里的“纯切割”采用可执行的拓扑定义：同一道路系列、两支连续、无其他分支。现有字段无法证明某点历史上是否经过某次切割操作；方案不依赖这种不可验证的历史信息。

不同道路名称或类型在 degree=2 的位置接触，P0 按不同道路组接触点保留。如果数据存在单纯改名、等级变更且希望排除，需要提供连续道路映射；本版不自动猜测。

## 8. 交点事件定位与排序

### 8.1 普通简单片段

对定向后的片段计算节点位置：

```sql
SELECT f.run_id, f.route_id, f.fragment_id, f.frag_seq,
       n.node_id,
       ST_LineLocatePoint(
           CASE WHEN f.direction = 1
                THEN ST_Reverse(f.geom) ELSE f.geom END,
           n.geom
       ) AS fraction
FROM node_source s
JOIN road_fragment f
  ON f.run_id = s.run_id AND f.fragment_id = s.fragment_id
JOIN road_node n
  ON n.run_id = s.run_id AND n.node_id = s.node_id
WHERE f.run_id = :run_id
  AND n.is_kept
  AND ST_IsSimple(f.geom)
  AND NOT ST_IsClosed(f.geom)
  AND ST_DWithin(f.geom, n.geom, :numeric_eps_deg);
```

同一 node_source 若有多条来源候选关系，定位前先对 `(run_id,node_id,fragment_id)` 去重。

`ST_LineLocatePoint` 给出点在 LineString 上的最近位置比例，并不是“点确实在线上”的证明，因此必须有来源关系和距离复核。[10]

### 8.2 自交或闭合片段

同一节点可能在片段内出现多次，不能只调用一次整线 `ST_LineLocatePoint`。改为在定向后的基本直线段上定位。

设基本段 j 长度为 `L(j)`，前面基本段累计长度为 `C(j)`，节点在基本段上的局部比例为 `u`，整条片段总长度为 `L`：

```text
fraction = [C(j) + u × L(j)] / L
```

这里统一使用 4326 geometry 的平面长度计算比例，和普通 `ST_LineLocatePoint` 的顺序语义一致；此长度只用于排序，不作为米制输出。

同一顶点在相邻基本段被重复定位时，只合并累计位置相同的重复事件。自交点位于不同累计位置时，必须保留多次出现。闭合片段起终点对应 0 和 1，交点事件按环状规则处理，不任意删掉其一。

### 8.3 跨片段重复事件

交点恰好位于前一片段末端和后一片段起点时，会被记录两次。仅在以下条件全部满足时合并：

- route_id 和 node_id 相同；
- 是相邻 frag_seq；
- 前一事件位于定向片段末端，后一事件位于定向片段起点；
- 两端实际在数值容差内连接，没有跨缺口。

保留两个来源片段到合并事件的追溯关系。不得简单按 `(route_id,node_id)` 全局去重。

最后按 `(frag_seq,fraction)` 排序生成 `event_seq`。同一排序位置出现不同 node_id 时，先复核节点归并，不用 node_id 强行打破并列。

## 9. 生成相邻交点直线

### 9.1 开放道路

仅对 `edge_ready=true` 的道路执行窗口函数 `LEAD`。输入为已完成去重、排序的 road_node_event：

```sql
WITH events AS (
    SELECT e.run_id, e.route_id, e.event_seq, e.event_id,
           e.node_id, n.geom
    FROM road_node_event e
    JOIN road_node n
      ON n.run_id = e.run_id AND n.node_id = e.node_id
    JOIN road_route r
      ON r.run_id = e.run_id AND r.route_id = e.route_id
    WHERE e.run_id = :run_id AND r.edge_ready
), paired AS (
    SELECT *,
           lead(event_id) OVER w AS next_event_id,
           lead(node_id)  OVER w AS next_node_id,
           lead(geom)     OVER w AS next_geom
    FROM events
    WINDOW w AS (PARTITION BY run_id,route_id ORDER BY event_seq)
), lines AS (
    SELECT run_id,route_id,event_seq AS edge_seq,
           event_id AS start_event_id,next_event_id AS end_event_id,
           node_id AS start_node_id,next_node_id AS end_node_id,
           ST_MakeLine(geom,next_geom)::geometry(LineString,4326) AS geom
    FROM paired
    WHERE next_event_id IS NOT NULL
      AND node_id <> next_node_id
      AND NOT ST_Equals(geom,next_geom)
)
SELECT *, ST_Length(geom::geography) AS length_m
FROM lines;
```

用两个 Point 调用 `ST_MakeLine`，结果为只包含这两个端点的线。[11] 不使用 `ST_LineSubstring` 保留原始弯曲线，因为本任务要求交点直连。

在执行上面过滤前，必须先将相邻事件相同节点或相同坐标的情况记录为 `ZERO_LENGTH_OR_LOOP`。若它代表真实绕行后返回同一点，两个点的直线无法表达这一回路；不能将其误算为成功生成了一条有效线。

### 9.2 缺失片段

两个交点之间无论跨多少个现存片段，仍然直接生成一条线。相邻编号片段端点不连接时记录一个 `gap`，并记录其端点距离。

通过 frag_seq 前缀和统计每条输出边跨过的 gap 数量；无需为每条边扫描全部中间片段。不把 osm_id 的数值差当作缺失数量。

输出 `gap_count`、`max_gap_m`、`orientation_quality`、`has_rejected_input`。其中 gap_count 只表示已观察到的不连续接缝数量，不声称知道实际缺失了多少条片段。

### 9.3 闭环道路

只有数据证明道路闭合时才补最后一个交点到第一个交点的线。定向前检查首、末片段的端点组合，存在数值容差内重合时列为闭环候选；再验证完整有序链能满足该闭合约束。不得只看开放链最优定向的结果，否则可能漏掉本来可闭合的方向方案。不能根据名称含“环路”就闭合，也不能因首尾较近而闭合。

对于单个闭合片段，可在原始顶点中选取确定性的非交点位置作为排序起点，旋转顶点序列；若所有顶点都是交点，则选择确定性的交点起点并只保留环形序列的一份首尾事件。旋转不改变原始形状。

环形定向要把末端到起点的连接作为约束，分别固定首状态为 0 和 1 运行动态规划后比较；不能先按开放链定向再随意补一条闭合边。

- 三个及以上交点：输出顺序相邻边以及最后到最初的一条边。
- 两个不同交点：环上两段均表示为两点直线，几何可能重合，但保留不同事件边和 edge_seq，不按几何去重。
- 零个或一个不同交点：不生成零长度环线，记录 `INSUFFICIENT_DISTINCT_NODES`。
- 缺失发生在无法证明闭合的位置：按开放序列处理，不推测首尾连接。

### 9.4 最终输出字段

| 字段 | 含义 |
| --- | --- |
| run_id、route_id、edge_seq | 本批次内线段标识 |
| city_code、county_code、road_name、type | 道路业务归属 |
| start_node_id、end_node_id | 空间端点 |
| start_event_id、end_event_id | 道路经过事件，支持同一点多次出现 |
| start_fragment_id、end_fragment_id | 端点来源；更多来源通过事件关联表追溯 |
| geom、geometry_wkt | 4326 两点 LineString 及导出 WKT |
| length_m | 两端之间连接线的米制长度 |
| gap_count、max_gap_m | 跨越的不连续接缝情况 |
| quality | CONNECTED、INFERRED_GAP 等可解释质量标记 |

道路来源归属来自原始数据，不能根据新直线落在哪个区县重新分配；新直线可能偏离原道路甚至越出原道路所在范围，这是直线化的几何结果。

## 10. 异常隔离与完成判定

| 异常 | P0 处理 |
| --- | --- |
| 无法解析、零长度、非 LineString | 原始记录入异常表，不进入空间运算；关联道路标记输入不完整 |
| 自然键冲突、osm_id 顺序冲突 | 对应道路不发布线段，等待输入映射修正 |
| 无法识别高架排除依据 | 批次预处理不完成，不把未过滤结果作为正式结果 |
| 重合线、自重叠 | 保留可计算交点，涉及道路不发布线段 |
| 聚类或局部拓扑不能确认 | 关联道路不发布线段，避免跳过未判明节点后错误连线 |
| 方向歧义改变交点配对 | 对应道路不发布线段；不影响其他道路 |
| 跨缺失片段但方向已按规则选定 | 允许输出，标记 INFERRED_GAP |
| 少于两个交点 | 正常无边结果，单独统计，不当作任务失败 |
| 同一节点的真实回绕无法表达为非零直线 | 保留事件与异常；该位置不生成零长度结果 |

运行结束必须分别统计“成功产出道路”“正常无边道路”“存在阻塞异常道路”。不得把道路无结果一律解释为没有路口。

允许发布不受影响的道路结果；整体批次状态注明 `COMPLETED_WITH_ISSUES`。用户接受自然缺失，不等于接受将已知排序或拓扑错误静默发布。

## 11. 十万片段规模的执行安排

十万片段不做全部无索引两两求交。先利用包围盒与 GiST 索引筛选空间候选，再计算精确相交。

1. 导入、清洗、分组后建立索引并 ANALYZE。
2. 按左表 fragment_id 分批求交，右表始终保持全城范围。
3. 点状交集、线状异常分别物化，避免重复调用 ST_Intersection。
4. 节点局部拓扑按节点批处理，只处理有关联来源的片段。
5. 普通简单片段直接定位；仅自交、闭合等复杂片段展开基本段，避免无条件放大全城顶点表。
6. 交点归并、道路事件排序按 run_id 分区，在完整来源收集后执行，不能各求交批次独立去重后直接拼接。
7. 一次只发布通过校验的运行版本，通过事务更新当前版本指针；中途失败不能覆盖上一版完整结果。

评估记录总片段数、总顶点数、空间候选对数、实际相交对数、候选点数量、各步骤耗时与磁盘占用。十万条并不决定固定运行时长，复杂长折线、重叠密集度和顶点数会显著影响性能。

若少数长折线导致包围盒过大，再增加按顶点窗口拆分的检索辅助表：保留父 fragment_id，相邻窗口共享一个端点，保证完整覆盖原线；先获得并去重父片段候选对，再对原始完整片段求交。辅助切分点不进入业务节点。P0 首版不预先增加该优化。

## 12. 验收用例与结果约束

### 12.1 最小用例集

| 用例 | 预期结果 |
| --- | --- |
| 两条道路十字相交 | 一个节点，度数 4，关联两条道路 |
| 丁字口，支路端点接主路内部 | 一个节点，度数 3，不能因是端点删除 |
| 同一道路两个片段仅连续连接 | 连续点排除 |
| 同一道路片段连接处恰好还有第三条支路 | 保留真实路口 |
| 不同道路首尾接触 | ROAD_CONTACT 保留 |
| 相同道路仅在区县边界拆组 | degree=2 的边界点不作为路口 |
| 一对复杂片段有两个交点 | 两点全部保留，不能只取第一个 |
| 三个以上片段共用一个交点 | 一个节点，多条来源关系 |
| 片段 WKT 方向交替反转 | 定向后交点次序正确 |
| 两个已有交点之间缺片段 | 仍输出一条直线，记录缺口 |
| 缺失位置原本可能有未知路口 | 不虚构该路口 |
| 一个片段自交并两次经过同一点 | 一个空间节点，多个道路事件 |
| 交点恰好落在两片段共同端点 | 道路内只形成一次连续经过事件 |
| 线状重叠、包含重叠与独立点的混合交集 | 重叠异常记录；独立点不丢失；关联道路不静默成线 |
| 两个距离很近但不同的路口 | 不按米级距离合并 |
| 方向代价相等且对应不同交点配对 | 不随意输出；记录歧义 |
| 闭环有三个交点 | 三条顺序相邻直线，包含末点到首点 |
| 闭环只有两个交点 | 两个事件边可几何重合，不按几何删除一条 |
| 一个道路只有零个或一个交点 | 正常无输出线段 |
| 输出直线穿过第三条道路 | 不产生新交点 |
| 同名同类型但包含独立平行链 | 验证来源序列契约；不能证明单链时要求拆组，不擅自串线 |

### 12.2 必须满足的约束

- 所有输出几何均为非空、非零长度、SRID=4326 的两点 LineString，`ST_NPoints(geom)=2`。
- 输出端点与引用 road_node 的坐标一致。
- 每条边连接同一 route_id 的相邻事件；闭环仅额外允许末事件到首事件。
- 无异常且无重复返回节点的开放序列有 k 个事件时，输出 `max(k-1,0)` 条边；闭环的计数按第 9.3 节校验。
- 所有候选点均可追溯到原始片段点状交集或片段自交；缺失补连不能成为候选来源。
- 排除的纯连接点具有明确 degree、road_family_id 集合和分类原因。
- 不同道路之间不共用一个排序窗口。
- 输入乱序不能改变规范化后的结果；比较业务键、节点坐标和事件配对，不比较数据库自增 ID。
- 重复运行不能追加重复边或混入其他 run_id 的中间数据。
- 线段数量、异常数量和各类无输出原因能够对账。

首轮先用上述小型构造数据核验，再用一个城市的数据全量运行，按节点类型和异常类型抽样检查。SQL 执行计划重点检查空间索引是否有效，以及是否出现大量重复求交。本文给出实现契约、算法及关键 SQL；完整存储过程仍需按这些用例在目标 PostGIS 实例中验证。

## 13. 实施交付拆分

| 实施单元 | 主要实现 | 验收产物 |
| --- | --- | --- |
| 输入与配置 | 导入校验、类型排除、名称清洗、road_family/route 映射 | 合格片段表、输入异常表 |
| 原始交点 | 索引自连接、批次求交、自交检测、交集分类 | 候选点、来源关系、重叠异常 |
